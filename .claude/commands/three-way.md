`$ARGUMENTS` 소재로 **뉴스 · 캐러셀 · 블로그** 3종을 만듭니다.
소재를 안 주면 `knowledge/reference/backlog.md` 에서 점수 높은 것을 고르세요.

## 반드시 먼저 읽기

1. `knowledge/patterns/3way-repurpose.md` — **채널별 역할 분담 (핵심)**
2. `knowledge/sources.md` — 라이트 소재(툴 업데이트) 출처 + 선별 기준
3. `knowledge/brand-facts.md` — 표기 고정값, 인용 가능 수치
4. `knowledge/banned-words.json` — 금칙어, swipe 승인 목록

## 소재 범위

**주력은 라이트 소재**입니다 — 구독료 변경 · 새 모델 출시 · 새 기능.
주요 툴: **클로드(코드) · 러버블 · Codex · Gemini**.

무겁고 추상적인 주제(AI 윤리, 거대 담론)는 블로그에 쓸 경험이 안 나오므로
3way 소재로는 부적합합니다. 가끔만 섞으세요.

## 사실 확인 (생략 금지)

- 기능·요금은 **공식 체인지로그/요금 페이지 원문**에서 확인
- 요금은 국가·시점별로 다르므로 **확인 날짜를 반드시 기록**하고 산출물에 시점 명시
- 확인 못 한 수치는 **쓰지 않습니다** (추정치 금지)

## 산출물

`output/<topic>/` 아래에:

### 1) `news.md` — 뉴스 (먼저)
- 300~500자. 첫 문장에 결론
- 무엇이 · 언제부터 · 얼마에 · 누가 쓸 수 있나
- 해석 금지 (그건 캐러셀·블로그 몫), 공식 출처 링크 필수
- 마지막 한 줄로 캐러셀 예고

### 2) `templates/slides.v5.<topic>.json` → 캐러셀
- 사실은 1~2장으로 압축, 나머지는 **교실 번역**
- 만들고 나서 바로 실행:
  ```bash
  node scripts/make-carousel.mjs --data templates/slides.v5.<topic>.json --topic <topic>
  ```
- `caption.md` 도 함께 작성 (캡션 첫 줄은 뉴스 제목과 **다르게**)

### 3) `blog.md` — 블로그 (마지막)
- **"직접 써봤다"가 없으면 초안만 만들고 발행 보류**로 표시
- 구성: 뭐가 바뀌었나(짧게) → 직접 해본 과정 → 안 되던 것 → 교실 적용 → 결론
- 스크린샷 자리를 `> [스크린샷: 설명]` 으로 표시해두기
- 제목은 **검색어 기준** (인스타 후킹 제목과 다르게)

## 중복 방지 체크 (마지막에 반드시)

- [ ] 제목 3개가 서로 다른가 (사실형 / 후킹형 / 검색형)
- [ ] 첫 문장 3개가 서로 다른가
- [ ] 마무리가 다른가 (예고 / 저장 / 구독·책)
- [ ] 같은 문장이 두 곳에 그대로 들어가지 않았나
