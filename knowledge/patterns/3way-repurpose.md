# 3way-repurpose.md — 한 소재 → 캐러셀 · 블로그 · 뉴스

> 소재 하나로 세 곳을 채웁니다. 리서치 비용은 1/3, 노출은 3배.
> **단, 복붙하면 셋 다 죽습니다.** 각 채널의 일이 다릅니다.

---

## 핵심 원칙 — 셋이 하는 일이 다릅니다

| | 뉴스 | 캐러셀 | 블로그 |
|:---|:---|:---|:---|
| **채널** | 무궁무진 클래스 커뮤니티 · AI뉴스 | 인스타 `@yongssam.dev` | 딸깍교실 |
| **독자** | **이미 회원** (따뜻함) | 처음 보는 사람 (차가움) | 검색해서 온 사람 |
| **일** | 사실 전달 | 의미 번역 | 경험 증명 |
| **속도** | 당일~다음날 | 1~2일 뒤 | 3~7일 뒤 |
| **길이** | 400~800자 | 9장 + 캡션 | 2,000자+ |
| **독자 상태** | "무슨 일 있었어?" | "그래서 나한테?" | "어떻게 하는데?" |
| **승부처** | 빠르기·회원 유지 | 저장·신규 유입 | 검색 유입 |
| **링크** | ✅ 클릭됨 — 공식 출처 바로 걸기 | ❌ 본문 링크 안 됨 | ✅ 클릭됨 |
| **수명** | 3일 | 2주 | 2년 |

**독자 온도가 다르다는 게 핵심입니다.** 커뮤니티는 이미 나를 아는 사람들이고,
인스타는 나를 처음 보는 사람입니다. 같은 문장이 통할 리가 없습니다.

**같은 사실을 세 번 말하는 게 아니라, 한 사실을 세 단계로 소화시키는 것**입니다.

---

## 순서 — 뉴스 → 캐러셀 → 블로그

이 순서인 이유:

1. **뉴스가 먼저인 건 속도가 유일한 무기**라서. 하루 지나면 가치가 반토막
2. **캐러셀이 중간인 건 정리할 시간이 필요**해서. 뉴스 반응 보고 각도를 정할 수 있음
3. **블로그가 마지막인 건 직접 써봐야** 해서. 며칠 써보고 쓰는 글이라야 다름

⚠️ **블로그를 먼저 쓰지 마세요.** 안 써보고 쓰면 뉴스 요약이 되고, 그건 이미 뉴스에서 했습니다.

---

## 채널별 작성 규칙

### 1) 뉴스 — 무궁무진 클래스 커뮤니티 AI뉴스

**여긴 우리 회원들입니다.** 자기소개도, 후킹도 필요 없습니다. 바로 본론.

- **첫 문장에 결론.** "클로드 코드에 ○○ 기능이 추가됐습니다."
- 무엇이 · 언제부터 · 얼마에 · 누가 쓸 수 있나. 이 4개가 뼈대
- **링크가 클릭되는 유일한 채널** → 공식 체인지로그·요금 페이지를 본문에 직접 걸기
  (인스타에서는 못 하는 걸 여기서 해줘야 회원인 값어치가 생깁니다)
- 요금·기능은 **확인 날짜 병기** ("2026-08-04 공식 페이지 기준")
- **한 줄 코멘트는 허용**: "이건 우리 반 앱 만들 때 바로 씁니다" 정도.
  단, 긴 해석은 캐러셀·블로그 몫이니 넘기지 마세요
- **마지막은 질문으로 닫습니다.** 커뮤니티는 댓글이 생명입니다.
  "혹시 벌써 써보신 분 계신가요?" → 예고보다 질문이 낫습니다

#### ⭐ 형식 — 마크다운 금지, 신문 기사체로

뉴스는 **글로 읽히는 기사**입니다. 문서가 아닙니다. 다음을 지키세요.

| 쓰지 말 것 | 대신 |
|:---|:---|
| `#` `##` 제목 기호 | 제목은 첫 줄에 그냥 한 줄 |
| `**굵게**` `*기울임*` | 강조는 문장 순서로. 중요한 건 앞에 씁니다 |
| 표 (`\| \| \|`) | 문단으로 풀어쓰기. 날짜·버전은 문장 안에 |
| `-` 불릿 나열 | 문단으로 잇기 |
| `---` 구분선 | 문단 사이 빈 줄 |

- **본문은 `~했다` 기사체**로 씁니다. 리드 문단에 누가·무엇을·언제를 다 담고,
  이후 문단은 시간 순 또는 중요도 순으로 풉니다
- **마지막 댓글 유도 한 줄만 `~습니다` 존댓말**로 돌아옵니다.
  기사 본문과 편집자 한마디를 구분하는 장치입니다
- 링크는 마크다운 `[제목](url)` 이 아니라 **주소를 그대로** 적습니다.
  커뮤니티 게시판이 마크다운을 렌더링하지 않으면 기호가 그대로 노출됩니다

> 왜: 마크다운이 살아 있는 초안을 게시판에 붙이면 `#` 과 `**` 가 글자로 남습니다.
> 렌더링이 되더라도 문서처럼 보여서 기사로 안 읽힙니다.

#### 난이도 — 뉴스도 쉬워야 합니다

회원 대상이라고 전문적이어도 되는 게 아닙니다. 커뮤니티 회원 대부분은
**클로드 코드를 안 써본 교사**입니다. `sources.md` 의 "교무실 옆자리 테스트"가
뉴스에도 그대로 적용됩니다.

- 기능 이름을 그대로 제목에 쓰지 말 것 (`/verify` → "자동으로 검사해주던 기능")
- 버전 번호는 본문 안에서만, 제목·리드에는 넣지 말 것
- 낯선 단위(토큰·크레딧)는 **첫 등장에서 한 번 풀어쓰기**

### 2) 캐러셀 — 교실로 번역

- 뉴스에서 쓴 **사실은 1~2장으로 압축**. 나머지 7장은 "그래서 뭐가 달라지나"
- 반드시 **교실 상황**으로 치환 (일반 사용자 얘기로 끝내면 남들과 같아짐)
- 숫자가 있으면 시각화 (막대·스탯·도트)
- 캡션 첫 줄은 뉴스 제목을 **그대로 쓰지 말고** 다시 후킹
- Outro는 저장 CTA 1개 + 엔드카드

### 3) 블로그 — 직접 해본 것만

- **"제가 써봤습니다"가 없으면 발행하지 마세요.** 그게 유일한 차별점
- 필수 구성: 뭐가 바뀌었나(짧게) → **직접 해본 과정** → 안 되던 것 → 교실 적용 예시 → 결론
- 스크린샷 2장 이상. 없으면 신뢰가 안 붙음
- 제목은 검색어 기준으로 (인스타 후킹 제목과 다르게 씀)
- 캐러셀 이미지를 본문에 재활용해도 좋음 (같은 톤이라 브랜드가 쌓임)
- 톤·구조는 `ddalkak-posting` 스킬의 3대 원칙을 따름

## 중복을 피하는 한 가지 장치

**같은 문장을 두 곳에 쓰지 마세요.** 특히 이 세 개는 반드시 다르게:

| | 다르게 써야 할 것 |
|:---|:---|
| 제목 | 뉴스는 사실형 / 캐러셀은 후킹형 / 블로그는 검색형 |
| 첫 문장 | 셋 다 다른 문장으로 시작 |
| 마무리 | 뉴스는 예고 / 캐러셀은 저장 / 블로그는 구독·책 |

같은 제목을 세 곳에 쓰면 알고리즘이 중복으로 보고, 독자는 "아까 본 거"라고 느낍니다.

## 서로 연결하기

- **커뮤니티 뉴스 →** 며칠 뒤 "이 내용 카드뉴스로 정리했습니다" + 인스타 링크
  (링크가 클릭되니 여기서 인스타 팔로워를 데려올 수 있습니다)
- **캐러셀 →** 캡션에 "직접 써본 후기는 블로그에" (링크는 프로필)
- **블로그 →** 본문에 캐러셀 이미지 재활용 + 책 홍보 블록 + 커뮤니티 가입 유도

**순환 구조**: 커뮤니티(회원) → 인스타(신규) → 블로그(검색) → 다시 커뮤니티.
링크가 되는 두 곳(커뮤니티·블로그)이 링크가 안 되는 인스타를 밀어주는 그림입니다.

한 소재가 세 곳을 돌며 서로를 밀어줍니다.

---

## 라이트 소재가 3way에 특히 잘 맞는 이유

구독료 변경 · 새 모델 · 새 기능 같은 **툴 업데이트**는:

- 사실이 명확해서 **뉴스로 쓰기 쉽고**
- 변화가 눈에 보여서 **캐러셀로 시각화하기 좋고**
- 직접 써볼 수 있어서 **블로그에 경험을 쓸 수 있습니다**

반대로 "AI 윤리" 같은 무거운 주제는 직접 해볼 게 없어서 블로그가 약해집니다.
**주력은 툴 업데이트로 가고, 무거운 주제는 가끔** 섞는 게 운영이 편합니다.
